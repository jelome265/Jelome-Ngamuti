# Information Architecture

## Page model

Start with a **single-page portfolio** using section navigation. Add dedicated project case-study routes only when a project has enough verified content to justify a separate page.

## Navigation

Primary navigation:
- Home
- Projects
- About
- Contact

Use a compact header. On desktop, display these links inline. On small screens, use an accessible menu button with an expanded/collapsed state. Navigation items should link to real sections; do not include placeholder pages.

## Content order

1. **Header** — name/wordmark and primary navigation.
2. **Hero** — name, concise role/focus statement, short value proposition, primary “View projects” action, and secondary contact/GitHub action.
3. **Selected projects** — a small, curated set of real projects. Give each project a clear summary, status, technology context, contribution, and relevant source/demo links.
4. **Technical focus** — group technologies by meaningful areas and support them with project evidence rather than unsupported proficiency ratings.
5. **About** — brief background, current learning/education context, and engineering principles.
6. **Contact** — clear invitation and verified contact links.
7. **Footer** — concise navigation, copyright year, and GitHub link.

Section names may change during visual design, but their meaning and hierarchy should remain clear.

## Content hierarchy

- **Level 1:** identity and engineering focus.
- **Level 2:** selected work and primary actions.
- **Level 3:** project context, technical choices, current status, and supporting background.
- **Level 4:** secondary metadata such as dates, technologies, and external references.

Project cards should prioritize the project name, problem/purpose, contribution or outcome, and a next action. Technologies are supporting metadata, not the headline.

## Project case-study structure

When a separate case study is justified, use:
- Overview and current status.
- Problem and intended users.
- Scope and personal contribution.
- Architecture or key technical decisions.
- Challenges, trade-offs, and evidence.
- What remains incomplete or is planned.
- Source repository and live demo, if actually available.
- Previous/next project navigation where helpful.

## Calls to action

- Primary: view selected projects.
- Secondary: contact or view GitHub.
- Per project: inspect source and, where available, open the live demo.

Do not offer a download, demo, email, or social destination until the target exists and has been checked.
